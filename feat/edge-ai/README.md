# Edge AI Engineer: feat/edge-ai

Use case: **traffic congestion prediction**, run locally on an edge node next to the traffic sensor.
The node pulls the latest standardized records through the traffic provider API (policy-checked,
under a data-sharing contract), predicts locally with an **ONNX** model and publishes **only the
prediction** as the derived dataset `traffic_sensor_1.congestion_forecast`. Raw training data stays on the node.

## Model

| | |
|---|---|
| Target | congestion (sensor `incident` flag) within the next 6 records (~30 s), so the model has to anticipate *onset* |
| Features (12) | current speed / density / incident, window mean & min speed, mean & max density, density and speed slopes, incident ratio, hour (sin/cos), computed over the last 6 records ([`edge_ai/features.py`](edge_ai/features.py)) |
| Algorithm | Random forest, 60 trees, depth 10, class-balanced |
| Edge format | ONNX opset 17, served with ONNX Runtime |
| Data | 3 simulated days (51,840 records) from Module 1's seeded traffic simulator, chronological 80/20 split |

Results on the held-out last 20% ([`reports/evaluation.md`](reports/evaluation.md), regenerated by `train.py`):

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| **Random forest (ONNX)** | 0.843 | 0.554 | 0.825 | **0.663** | **0.863** |
| Logistic regression | 0.834 | 0.537 | 0.827 | 0.651 | 0.854 |
| Persistence baseline ("incident now") | 0.866 | 0.792 | 0.387 | 0.520 | n/a |

The baseline has higher accuracy because it never predicts onset. The model trades precision for
recall, catching 83% of upcoming congestion instead of 39%. The simulator's state transitions are
random, so onset is only partly predictable from the recent window.

| Benchmark (CPU, Windows) | scikit-learn | ONNX Runtime |
|---|---|---|
| Model size | 2.9 MB | 1.2 MB (−58%) |
| Single prediction (mean) | 17.2 ms | 0.085 ms |
| Batch of 1000 (mean) | 28.9 ms | 33.8 ms |

The edge workload is one prediction every few seconds, so single-prediction latency is what matters.
The ONNX output matches the original model to within 4e-7.

## Run

```powershell
pip install -r requirements.txt
python train.py                         # train + evaluate + export ONNX + benchmark (~1.5 min)
python train.py --source api            # train on records pulled from the provider API instead
uvicorn edge_ai.service:create_app --factory --port 8020    # Swagger: http://localhost:8020/docs
python -m pytest -q                     # 7 tests
```

The Docker image only installs [`requirements-runtime.txt`](requirements-runtime.txt) (ONNX Runtime,
no scikit-learn) and ships `models/congestion_rf.onnx` + `models/metadata.json`.

| Variable | Default | Role |
|---|---|---|
| `EDGE_PORT` | 8020 | listening port |
| `TRAFFIC_API_URL` | `http://localhost:8001` | provider API to read from and publish to |
| `DATA_SPACE_URL` | `http://localhost:8010` | used to negotiate the data-sharing contract |
| `EDGE_API_KEY`, `EDGE_PARTICIPANT_ID` | empty, `edge_node_1` | edge node identity |
| `EDGE_PURPOSE` | `congestion_prediction` | declared purpose |
| `EDGE_POLL_SECONDS` | 5 | loop period |
| `EDGE_LOOP_ENABLED` | true | disable to serve `/predict` only |
| `CORRIDOR_KM` | 5 | corridor length used for the travel-time estimate |

## API

- `POST /predict {"records": [...]}`: probability, `congested`, `traffic_level`
  (free_flow / moderate / heavy / severe), estimated travel time, inference latency.
- `GET /model-info`: features, metrics, benchmark, model version.
- `GET /predictions/latest`, `GET /predictions?limit=`: loop results.

The travel time is a heuristic (corridor length / recent mean speed), not a learned output.
